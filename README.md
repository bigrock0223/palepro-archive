# パレプロ アーカイブ検索（試作）

Palette Project の配信アーカイブを、日時・メンバー・ジャンル・キーワードで検索できる非公式ファンサイトの試作です。
サーバー・DB 不要、GitHub Pages（無料）で公開できる構成です。

## 手元で画面を見る

`public/index.html` をブラウザで開くだけで動きます（`public/data/archives.js` が必要。`node scripts/build.mjs` で作られます）。

## フォルダ構成

```
config/
  channels.json      … 監視するチャンネル（メンバー名・色・@ハンドル・並び順）
  genres.xlsx        … ジャンル管理用Excel（ここの○がサイトのジャンルになる）
  genre-rules.json   … ジャンル自動判定のキーワード（Excel未登録の新着に使う）
  cast.json          … 出演者・ユニット自動判定の設定（名前・愛称・ユニット・コンビ・デビュー日）
  site-edits.json    … 確認モードでの確認結果・修正（確認モードが自動で書き込む。手で編集しない）
  overrides.csv      … 予備の手動ジャンル（通常は使わない）
tools/
  append_xlsx.py     … genres.xlsx に新着を差し込む（書式を残す。Python + openpyxl）
  export_xlsx.py     … genres.xlsx を一から作り直す（Python + openpyxl）
  add_cast_columns.py … genres.xlsx に「出演:」「ユニット:」列を差し込む（書式を残す）
  import_site_edits.py … 確認モードの結果（site-edits.json）を genres.xlsx に取り込む（書式を残す）
scripts/
  fetch.mjs          … YouTube API から取得 → data/videos.json
  build.mjs          … ジャンル付け → public/data/archives.js
  xlsx-read.mjs      … genres.xlsx の読み込み（追加パッケージ不要）
  make-dummy.mjs     … ダミーデータ作成
data/videos.json     … 取得した生データ（自動更新がコミット）
public/              … 公開されるサイト本体（index.html / style.css / app.js）
                       確認モード（review.html / review.js / review.css）
.github/workflows/update.yml … 3時間ごとに自動取得して Pages に公開
.gitignore           … public/data/archives.js を GitHub で管理しない設定
```

## 本番データで動かす手順

1. **YouTube API キーを作る**
   Google Cloud Console でプロジェクト作成 → 「YouTube Data API v3」を有効化 → 「認証情報」で API キーを作成。
   キーの制限で「YouTube Data API v3 のみ」にしておくと安全です。
2. **チャンネルを設定**
   `config/channels.json` の `handle`（例 `@paletteproject`）を埋めます。空欄のメンバーは取得をスキップします。
   メンバー構成は最新の公式情報に合わせて増減してください。
3. **ローカルで試す（任意・Node.js 18以上）**
   ```
   set YT_API_KEY=取得したキー        (PowerShell なら $env:YT_API_KEY="...")
   node scripts/fetch.mjs --full
   node scripts/build.mjs
   ```
   `public/index.html` を開くと実データで表示されます。
4. **GitHub で公開**
   - このフォルダを GitHub リポジトリ（main ブランチ）に push
   - Settings > Secrets and variables > Actions > **Secrets** に `YT_API_KEY` を登録
   - Settings > Pages > Source を **GitHub Actions** に
   - Actions タブで `update-archives` を手動実行 → `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開
   - 以後は 3 時間ごとに自動更新

   ※ 初回は全件取得になるので、ローカルで `--full` 実行後の `data/videos.json` を一緒に push しておくと楽です。
   ※ ダミーデータのまま push した場合は、`data/videos.json` を削除してから実行してください。

## ジャンルを手で直す（Excel）

`config/genres.xlsx` がジャンルの元データです。

### 編集から反映までの流れ

1. `config/genres.xlsx` を Excel で開き、「ジャンル」シートで○を付け外しする（フィルターで絞り込むと一括修正しやすい）
2. 上書き保存（**.xlsx のまま**。CSV などで保存しない）
3. Excel を閉じてから、GitHub Desktop で Commit → Push
4. 自動更新が読み込み、数分後に公開サイトに反映される（Actions のログに「ジャンル管理Excel: ○○件」と出ていれば読み込み成功）

### ジャンルの決まり方

| 状態 | サイトでのジャンル |
|---|---|
| Excel に載っていて、○が1つ以上ある | Excel の○の付いたジャンルだけ（自動判定は使わない） |
| Excel に載っているが、○が1つもない | 自動判定（`genre-rules.json`） |
| Excel に載っていない新着 | 自動判定（`genre-rules.json`） |

### サイトに反映されるもの

- 「ジャンル」シート **1行目の見出し**（ジャンル名）
- **動画ID** 列
- ジャンル列の **○の有無**（○以外の文字でも、空欄でなければ「当てはまる」として扱う）

- **種類** 列（`配信` / `動画` / `ショート` のどれか）。書かれている値がサイトの種類になる（例：ショート機能がなかった頃の短い動画を `動画` に直す）。空欄や別の文字なら自動判定

- **確認済** 列。空欄でなければ確認済みとして扱い、確認モードに出てこない

上記以外（配信日時・メンバー・長さ・タイトル・URL・メモの内容）は参照用で、書き換えてもサイトには反映されません。

### 自由に変えてよいもの

- フォント、文字サイズ、色、列幅、行の高さ
- 並べ替え、フィルター、ウィンドウ枠の固定
- 「メモ」列の内容
- 「使い方」シートの内容

### 変えてはいけないもの

- シート名「ジャンル」
- 1行目の固定の見出し：`配信日時` `メンバー` `種類` `長さ` `タイトル` `確認済` `メモ` `動画ID` `URL`
  （ジャンル以外の列だと判断するために使っています。名前を変えるとジャンル列として扱われてしまいます）
- 動画ID の中身（消す・書き換えると、その動画は「Excel に載っていない」扱いになります）

### ジャンルの追加・名前変更・削除

- **追加**：列を挿入し、1行目にジャンル名を書く。場所はどこでもよいが、**既存のジャンル列の間（例：「冒頭無料」の左）に挿入するのがおすすめ**（「○だけ入力できる設定」と○の色付けが自動で新しい列にも広がるため。端に追加した場合はこの2つが付かないだけで、読み込みには影響しない）
  - ジャンル名に `出演:` `ユニット:` を付けない、固定の見出し（配信日時・メモ・動画ID など）と同じ名前にしない
- **名前変更**：1行目のジャンル名を書き換える。新着の自動判定でも新しい名前を使いたい場合は `genre-rules.json` 側も合わせて変更する（Claude に依頼可）
- **削除**：その列ごと削除する
- **並び順**：ジャンル列の左右の順番が、サイトでのジャンルの並び順になる

### 新着動画の追記

Excel にない新着動画は自動判定のジャンルで表示されます。新着を Excel に追記した版は Claude に依頼して作ってもらいます（`tools/append_xlsx.py` を使用）。

```
node scripts/build.mjs
python tools/append_xlsx.py public/data/archives.js config/genres.xlsx config/genres.xlsx
```

- 新着は見出しのすぐ下（2行目〜）に新しい順で差し込まれる。既存の行・○・メモ・列の並びはそのまま
- **フォントや色などの書式もそのまま残る**。新着行には、差し込み前の先頭データ行（2行目）と同じ書式が付く
- 入力規則（○だけ入力できる設定）・条件付き書式・フィルターの範囲も、追加した行まで自動で広がる
- 追記した行は「メモ」列に `新着（自動判定）` と入る。確認・修正したらメモは消してよい
- 自動判定のジャンルのうち Excel に列がないもの（例：Excel で名前を変えたジャンル）は、列を増やさずメモ欄に `列なし: ○○` と書かれる
- 追記を依頼する前に、Excel を閉じて手元の編集を Commit → Push しておく（編集途中のファイルを上書きしないため）
- 図形・画像・グラフなど、セル以外のものを Excel に追加した場合は、追記時に消えることがある

## 出演者・ユニット

検索画面の「メンバー（出演）」は、そのメンバーのチャンネルの動画に加えて、**他のチャンネルや公式チャンネルでそのメンバーが出ている動画**も対象になります。

- **全員出演**にチェック：選んだメンバーが全員出ている動画だけ（例：コトハ＋カナメのコラボ）
- **そのメンバーのチャンネルの動画だけ**にチェック：出演ではなくチャンネルで絞り込む（以前と同じ動き）
- 「Palette Project 公式」は常に公式チャンネルの動画で絞り込む
- **ユニット**欄：Sputrip / REGALILIA / RouteHeart / Alt!! / Altimate で絞り込む
- カードの「出演」に並ぶ名前やユニットを押すと、その条件が追加される

### 自動判定のしくみ（`config/cast.json`）

タイトルに次のどれかが含まれていれば出演者として付けます。チャンネルの持ち主は常に出演者です。

- フルネーム・名字・名前（例：暁月クララ / 暁月 / クララ）と愛称（例：くーちゃん、ぴよ、ちくわぶ）
- ユニット名（例：Sputrip、めちゃすぷ、レガギマ）→ そのユニットのメンバー全員 ＋ ユニットのタグ
- コンビ名（例：ろなめこ、ぴよノン）→ そのコンビのメンバー
- 公式チャンネルの「全員集合」「全員」→ その日までにデビュー済みのメンバー全員（`debut` の日付で判定）

カタカナとひらがなは区別して判定します（「ことはない」を「コトハ」と誤判定しないため）。卒業・休止メンバーとパレプロ外のゲストは対象外です。

### Excel での手直し

`config/genres.xlsx` の「出演:〇〇」（8列）と「ユニット:〇〇」（5列）で直します。

| 状態 | サイトでの出演者・ユニット |
|---|---|
| 出演・ユニットの列に○が1つ以上ある | Excel の○のとおり（自動判定は使わない） |
| 出演・ユニットの列に○が1つもない | 自動判定 |
| Excel に載っていない新着 | 自動判定（新着の追記時に自動判定の結果で○が入る） |

- ユニットに○を付けても出演者の○は自動では付かないので、出ているメンバーにも○を付ける
- 見出しの「出演:」「ユニット:」の部分は消さない（ジャンル列と区別するために使っています）
- 愛称・ユニット・コンビ・デビュー日を増やしたり直したりするときは `config/cast.json` を編集（Claude に依頼可）

## 確認モード（review.html）

自動判定や Excel の結果を、サイト上で1件ずつ（または一覧でまとめて）確認・修正する画面です。
`https://<ユーザー名>.github.io/palepro-archive/review.html` で開きます（鍵を登録したブラウザでは、検索サイトのフッターにもリンクが出ます）。

### 最初の準備：鍵（アクセストークン）を作る

1. GitHub 右上のアイコン → **Settings** → 左下の **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. 次のとおり設定する
   - Token name：`palepro-review` など
   - Expiration：90 days（切れたら作り直す）
   - Repository access：**Only select repositories** → `palepro-archive` だけを選ぶ
   - Permissions → Repository permissions → **Contents** を **Read and write**（Metadata は自動で Read になる）
3. **Generate token** を押し、表示された `github_pat_…` をコピー（この画面でしか表示されない）
4. `review.html` を開き、出てきた「鍵の設定」に貼り付けて「接続して保存」

- 鍵はそのブラウザの中にだけ保存される（PC とスマホは別々に登録）。共用 PC では使わない
- 漏れた心配があるときは、GitHub の同じ画面でその鍵を **Delete** すればすぐ無効になる
- 鍵なしでも「鍵なしで試す」で操作を試せる（結果はそのブラウザにだけ保存され、サイトには反映されない）

### 使い方

- **1件ずつ**：右側のボタンでタグを付け外しして **OK → 次へ**（Enter キーでも可）
  - 最初から今の判定結果にチェックが入っているので、合っていれば OK を押すだけ
  - **前の動画と同じ**：直前に OK した動画のジャンル・出演者・ユニットを写す
  - **Excel・自動判定に戻す**：確認モードで直す前の状態に戻す
  - **シリーズ**：同じ書き方のタイトル（例：【歌枠｜karaoke】）のまとまり。「未確認の◯件にも同じジャンル・ユニットを付けてOK」で、シリーズの未確認の動画をまとめて確認済みにできる（種類と出演者はそれぞれのまま）
- **一覧で一括**：カードを選び、右側のボタンを押すたびに「＋付ける」→「−外す」→「変更しない」と切り替わる。「選んだ動画に適用して確認済み」でまとめて反映
- **＋新しいジャンル**：ジャンル名と自動判定用のキーワード（任意）を入れて追加。追加後に「キーワードで探して付ける」画面が開き、過去の動画にまとめて付けられる
- **キーワードで探して付ける**（上部のボタン）：タイトルにキーワードを含む動画を探し、選んだジャンルをまとめて付ける
- **取り消し**（Ctrl+Z）：直前の操作を取り消す（保存したあとでも、次の保存で元に戻る）
- **保存**：20件ごと・2分ごとに自動で保存（Ctrl+S ですぐ保存）。保存すると GitHub の `config/site-edits.json` が更新され、数分後に公開サイトに反映される。保存前の分はブラウザに残るので、閉じても消えない
- 上部の絞り込みで、チャンネル・種類・要確認の理由・未確認／確認済みを切り替えられる

### 要確認の理由

| 理由 | 内容 |
|---|---|
| ジャンルが空（その他） | どのジャンルにも当てはまらない |
| 公式チャンネルで出演者が空 | タイトルに名前がない公式動画 |
| 個人チャンネルにユニット名 | 例：「Sputrip楽曲縛り」の個人歌枠（ユニット全員が出演扱いになっている） |
| 愛称・コンビ名だけで出演者を判定 | 「隊長」「ぴよ」などで判定した（Excel で出演者を指定していない動画のみ） |
| 全員回の自動付与 | 「全員集合」などでデビュー済み全員を付けた（同上） |
| 種類が微妙 | 3分以内で #shorts がない動画 |

### 優先順位と Excel への取り込み

- 優先順位：**確認モードでの確認・修正 ＞ Excel ＞ 自動判定**
- Excel の「**確認済**」列に日付などが入っている動画も確認済みとして扱う（確認モードに出てこない）
- 確認モードの結果は、時々 Excel に取り込んで一本化する（Claude に「確認モードの結果を Excel に取り込んで」と依頼）。`tools/import_site_edits.py` を使い、書式を残したまま ○・種類・確認済 を書き込み、追加したジャンルは列とキーワード（`genre-rules.json`）に登録して、`site-edits.json` を空に戻す
  ```
  python tools/import_site_edits.py config/genres.xlsx config/site-edits.json config/genre-rules.json
  ```
- 取り込みを依頼する前に、Excel を閉じて Commit → Pull origin → Push origin しておく

### 概要欄について

確認画面には概要欄の冒頭（300字）を表示します。この機能を入れる前に取得した動画の概要欄は、次回の自動更新でまとめて取り直します（API 使用量は数百ユニット程度）。

## 自動判定の調整（新着用）

`config/genre-rules.json` にキーワードを足すだけです。全角半角・大文字小文字・ひらがなカタカナの違いは自動で吸収します。
どれにも当てはまらないものは「その他」になります。

## 注意
- YouTube API の規約に沿って、取得から 25 日経ったデータは自動で取り直し、削除・非公開になった動画は消えます。
- サムネイルは YouTube の画像をそのまま表示しています（自前で保存しない）。
- 公開前に公式の二次創作ガイドライン（https://paletteproject.jp/guidelines）を確認してください。
