## 2. 検索サイトの画面（案A に決定）

ジャンル欄の「ゲーム」にチェックを入れると、そのすぐ下に、少し右に下げてゲームの種類の選択肢が出る。

```
┌ ジャンル ───────────────┐
│ □ 選んだジャンルをすべて含む │
│ □ 歌枠             1,862 │
│ ☑ ゲーム           3,333 │
│    □ 音ゲー          210 │   ← 「ゲーム」にチェック中だけ出る
│    □ RPG             480 │
│    □ アクション       390 │
│ □ 雑談             1,877 │
└────────────────────────┘
```

決めごとの案（実装時にユーザーに確認）：
- 子の選択肢が出るのは「ゲーム」にチェックが入っているとき。**子が1つでも選ばれていれば**、「ゲーム」の選択を外しても子は出たままにする（URL から開いたときに選択中の条件が見えなくならないように）
- 「ゲーム」の子の数が多いときは、ジャンル欄と同じように最初は数個だけ出し、「すべて表示」で開く
- **絞り込みの意味**：「ゲーム」と「音ゲー」を両方選んだら「ゲームのうち音ゲー」にする。子を選んだときは、親（ゲーム）の条件は子の条件に置き換える。こうしないと、「どれかを含む」の初期設定では「ゲーム全部」になってしまう
- 「選んだジャンルをすべて含む」が ON のときは、子どうしは「すべて含む」で判定する（例：音ゲー かつ アクション）
- 件数は、今のジャンルと同じく全体の件数で出す
- 一覧の動画のタグは「ゲーム › 音ゲー」のように出す。押すと、その種類で絞り込む
- URL は今の `genre=` に子の名前も入れる（例：`genre=ゲーム,音ゲー`）。新しい項目は増やさない
- スマホの全画面の絞り込みでも同じ形にする（行の高さは 44px）
- 見た目は DESIGN.md に従う（色・文字の大きさ・余白の決まり、6 のチェックリスト）。子の行の字下げは 16px

## 3. データの持ち方の案

**子ジャンルも「ふつうのジャンル名」として扱い、どの親の子かという対応だけを別に持つ**。この形にすると、今の仕組み（ジャンルの配列 g/m、確認モードの genres、シリーズ一括）をほぼそのまま使える。

### config/site-edits.json（確認モードが書く）
```json
{
  "newGenres": [
    {"name":"音ゲー","parent":"ゲーム","keywords":["プロセカ","太鼓の達人"],"added":"2026-12-01"}
  ],
  "videos": { "動画ID": {"reviewed":"2026-12-01","genres":["ゲーム","音ゲー"]} }
}
```
- `newGenres` に `parent` を足すだけ。`parent` がないものは今までどおりの親ジャンル
- 子ジャンルの名前は、ほかのジャンルとかぶらないようにする（例：「アクション」を親ジャンルとしても作らない）

### scripts/build.mjs
- `archives.js` に `genreParents: {"音ゲー":"ゲーム", ...}` を出す
- 動画に子ジャンルが付いていれば、親（ゲーム）も必ず付ける。付け忘れを防ぐため
- 子ジャンルのキーワード自動判定は、**親（ゲーム）が付いている動画にだけ**当てる。誤判定を防ぐため
- ジャンルの並び順（`genres`）では、子は親のすぐ後ろに並べる
- 要確認の理由（`reasons`）に「ゲームだが種類がない」（例：`noGameType`）を足す案がある。確認モードで「種類が未設定のゲーム」を順に片付けられる

## 4. 確認モードでやること

- ジャンルのボタンで「ゲーム」が ON のとき、その下にゲームの種類のボタンを出す（検索サイトの案Aと同じ考え方）
- 「＋新しいジャンル」の画面で、**親ジャンルを選べる**ようにする（なし／ゲーム）。キーワードは任意。追加したあとは、今の「キーワードで探して過去の動画にまとめて付与」がそのまま使える
- シリーズ一括（ジャンルとユニットだけ適用）で、子ジャンルも一緒に付けられるようにする（今の仕組みのままで付く見込み）
- 「前の動画と同じ」でも、子ジャンルが引き継がれることを確かめる
- 確認モードの見た目は、今のデザインのまま（ユーザー判断で、B案は検索サイトだけ）

## 5. ジャンル整備を確認モードに寄せる件（今回より大きい話。別に相談）

ユーザーは「ジャンルの整備は基本、確認モードで」「Excel は情報として持つだけ」と考えている。今の決まりとずれるところ：
- 今の優先順位は「確認モードの修正 ＞ **Excel** ＞ 自動判定」で、**Excel の○はサイトの表示に効いている**
- ジャンルの改名・削除・統合は、今は確認モードではできない
- `tools/import_site_edits.py` は、確認モードの結果を Excel に取り込んでから `site-edits.json` を空に戻す（＝一本化の先は Excel）

ゲームの種類を入れるだけなら、このままでも動く（子ジャンルは `site-edits.json` に持つ）。ただし、Excel に取り込んだときに子ジャンルを書く先が必要になる。たとえば Excel にジャンル列「音ゲー」を足すか、「ゲーム:音ゲー」のような列名にするか。→ 下の 6 で確認する。

## 6. 実装前にユーザーに確認すること

1. **ゲームの種類の一覧**（最初に作るもの）
   - 叩き台：音ゲー、RPG、アクション、ホラー、パズル、FPS・シューター、レース、スポーツ、シミュレーション、アドベンチャー、サンドボックス（マイクラなど）、パーティー・ボードゲーム、カード

2. **ゲームの名前から種類を自動で付けるキーワード**を最初に用意するか、確認モードで1件ずつ付けるだけにするか。用意するなら、よく遊ばれているゲームの一覧を作ってユーザーに見てもらう
3. **Excel の扱い**
   - 子ジャンルを Excel に記録するか。する場合、列の名前の付け方をどうするか
   - 「Excel は記録だけ」にするなら、Excel の○をサイトの表示に使うのをやめるか（優先順位の変更。影響が大きいので別の作業にするのがよい）
4. ゲーム以外のジャンル（例：歌枠の中の「アニソン」）にも子を作れるようにするか。仕組みは同じなので、最初から「どの親でも可」にしておくのもあり
5. 確認モードで、ジャンルの**改名・削除・統合**もできるようにするか（5 の話。やるなら別の作業）
